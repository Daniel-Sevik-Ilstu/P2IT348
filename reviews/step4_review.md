| 1 | Medium | src/models.py `train_all_from_split` (l.128-133) and `train_with_report` (l.136-144) | The year guard checks only the `years_train` array, which is metadata. It never looks at `X_train` or `y_train`. So it passes if `years_train` is mislabelled or has a different length from `X_train`/`y_train`, and it passes for an empty `years_train` (an empty set is `<= TRAIN_YEARS`). It does not use `check_no_overlap` or compare against `TEST_YEARS`, which PLAN.md section 0 says every train/predict call must go through. It also does not check that `y_train` contains only {0, 1} or that both classes are present; a one-class `y_train` makes `RandomForestClassifier` fit without error and give a degenerate model. On the real data everything is correct (I checked), so this is robustness, not a current bug. | Put the checks in one helper `_check_training_split(split)` that raises `ValueError` if `years_train` is empty, if `len(years_train) != len(X_train) != len(y_train)`, if the years are not a subset of `TRAIN_YEARS`, or if `set(np.unique(y_train)) != {0, 1}`. Also call `check_no_overlap(years, TEST_YEARS)` as PLAN.md section 0 asks. |
| 2 | Medium | src/models.py `train_with_report` (l.136-157) | Same guard code is copied from `train_all_from_split`, and `train_with_report` fits models itself instead of calling `train_all_from_split`. A later change to one guard will not reach the other. The only call that `main.py` makes goes through `train_with_report`, so `train_all_from_split` (the function PLAN.md names as the Step 4 entry point and that its tests target) is never used by the pipeline. The pipeline could pass its checks while the guard that actually runs is the copy. | Have `train_with_report` call the shared helper from comment 1 (or have it call `train_all_from_split` for the guard). Keep one place that fits the models. |

Every other warning raised while fitting (for example a sklearn `FutureWarning`/`UserWarning`) is recorded and then thrown away, and is not printed or written to the report. A `ConvergenceWarning` is also only counted, not raised, so a model that did not converge is still saved by `save_models` and would be used in Steps 5-7 (PLAN.md calls a ConvergenceWarning "a problem to report"). Today the count is 0 (I checked), so no result is affected. | After the `with` block, re-emit the non-convergence warnings (`warnings.warn_explicit` or `warnings.showwarning`) or store their messages in the report. For the convergence count, also log the model name and `n_iter_` so a hit is easy to trace. Decide whether `main.py` should stop on a non-zero count. |

On the current data the setting does nothing, since the training set is exactly 27,000 / 27,000 (I checked), and the code comment ("guard against imbalance in later use") is the only reason given. Step 7 compares logreg and sgd, so a hidden difference between them could confuse the comparison later if a window were ever imbalanced. | Either keep as is and say in the Step 4 report that the three models are effectively unweighted because the training data is balanced, or drop `class_weight` from logreg so logreg and sgd match. | 5 | Low | src/models.py (whole file) / PLAN.md "Step 4" | `tune_logreg` is in PLAN.md as "only if time allows" and is not implemented. This is acceptable, but then `C=1.0`, `alpha=1e-4` and `n_estimators=200` are all untuned defaults, and the diff gives no sign that the choice was checked on the 2016 validation year. The training accuracies (0.988-0.997) say nothing about whether these values generalise. | State in the Step 4 report that no tuning was done and that the values are defaults, not tuned on 2016.
